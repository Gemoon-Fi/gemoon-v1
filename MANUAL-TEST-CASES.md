# Ручные тест-кейсы фронтенда Gemoon

Сценарии для ручного QA: что пройти на фронте (`front/`), чтобы проверить работу протокола из конца в конец.
Автотесты контрактов описаны в [TEST-CASES.md](TEST-CASES.md). Здесь проверяется, что UI правильно показывает
и запускает то, что они покрывают: комиссии, анти-снайп, dev buy, стейкинг, награды, награды создателя.

Тексты UI в кейсах взяты из кода. Если текст на экране отличается, это повод завести баг или поправить кейс.

## 0. Окружение и подготовка

| Параметр | Значение |
|---|---|
| Стенд | https://dev.gmoon.xyz (выкладывается из ветки `develop`) или локально `npm run dev` → http://127.0.0.1:5173 |
| Сеть | Gemoon Anvil, **chain id 1488** (`0x5d0`), валюта ETH |
| RPC | https://rpc-testnet.gmoon.xyz |
| Explorer | https://otterscan.devinside.tech |
| Indexer | https://indexer.gmoon.xyz/graphql |
| Settlement-токен | USDG `0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168`, 6 decimals |
| Режим Swap | `VITE_SWAP_PROVIDER=uniswap` (Uniswap v4 на Anvil), `VITE_ENABLE_LIVE_SWAPS=false` |

### Подготовка кошельков

1. Добавить сеть в MetaMask вручную: Network name `Gemoon Anvil`, RPC `https://rpc-testnet.gmoon.xyz`, Chain ID `1488`, Symbol `ETH`, Explorer `https://otterscan.devinside.tech`. Старую сеть 1337 (`anvil.devinside.tech`) удалить.
2. Нужно минимум **3 аккаунта**. В UI нет faucet и mint, поэтому ETH и USDG выдаёт команда (стандартные Anvil-аккаунты по 10 000 ETH):
   - **A, создатель**: ETH и ≥ 1 000 USDG;
   - **B, трейдер/стейкер**: ETH и ≥ 1 000 USDG;
   - **C, второй стейкер**: ETH и ≥ 500 USDG.
3. Держать открытым Otterscan: каждую транзакцию сверять по hash (статус, события `TokenCreated`, `DevBuy`, `MemeSwapped`, `FeesConverted`).

### Константы протокола, которые видны в UI

| Константа | Значение | Где видно |
|---|---|---|
| Эмиссия мема | 1 000 000 000 | Review при создании (`Supply 1.0B`), Token info → Supply |
| Стартовая капитализация | 20 000 USDG (50 000 мемов за 1 USDG) | Market Cap нового токена |
| Комиссия мема (выбирает создатель) | 1%–10%, шаг 0.01%, по умолчанию 1% | Шаг 2 создания, Pool Tax |
| Анти-снайп | 80% в момент создания, линейно падает до комиссии мема за **30 с** | Total Tax / Pool Tax на странице токена |
| Доля протокола | 3333 bips (треть) от каждой комиссии | Review (`Protocol`), /testnet |
| Доля Vault | остаток комиссии; внутри неё 10% создателю, 90% стейкерам (без стейкеров 100% создателю) | Creator rewards, Staking rewards |
| Dev buy (Creator buy) | до 800 000 000 монет (80% эмиссии), платит базовую комиссию, без анти-снайпа | Шаг 3 создания |
| Порог конвертации | 5 USDG, cooldown 1 мин после сбоя | /testnet → Live protocol |
| Макс. активов в Vault | `Vault.MAX_ASSETS` (сейчас 5) | Шаг 2 создания |

### Общие правила проверки

- Значение, для которого нет проверенного источника, показывается как `–`. Заглушка (`0`, `$0.00`, выдуманное число) там, где данных нет, считается багом. Исключение: Staking-сводка без кошелька показывает `$0.00`.
- Деньги и количества **обрезаются**, а не округляются: `$999 995` выглядит как `$999.99K`. Проценты округляются до 2 знаков.
- Отказ в кошельке не должен оставлять форму в зависшем состоянии.
- Получение hash ещё не успех. Успех наступает только после receipt со статусом success.
- Каждый кейс прогнать на desktop и на mobile (≤ 760px).

## 5. Создание монеты (`/coin-creation`)

**Предусловия:** кошелёк A на сети 1488, есть ETH и USDG. В Vault allowlist должен быть хотя бы один
конвертируемый актив (USDG или актив с маршрутом в адаптере), иначе шаг 2 заблокирован (CC-20).
Для картинки подготовить публичный HTTPS URL изображения.

| NEG-04 | Смена аккаунта во время tx | Отправить Buy и сменить аккаунт до receipt | Toast `Account changed.` или корректное завершение, данные нового аккаунта не перемешаны со старыми |
| NEG-05 | Медленная сеть | DevTools → Slow 3G | Скелетоны вместо значений, нет мигания `0` → значение |
| NEG-06 | Sentry | Вызвать сбой (NEG-01) | В Sentry (project `gemoon`, env `develop`) есть событие с `feature`/`stage`. Отказ в кошельке событие **не** создаёт |
